# HR Exit Intelligence Engine & Web UI

Комплексное решение для сбора, анализа и визуализации данных выходных интервью (Exit Interview). Проект состоит из бэкенд-сервиса аналитики и API (`hr_exit_engine`), веб-интерфейса пользователя (`hr_exit_web`), а также скрипта пакетной обработки данных (`process_test_cases.py`), оркестрируемых через Docker Compose.

---

## 🏛 Архитектура проекта

* **`hr_exit_engine/`** — Бэкенд на Python (FastAPI / Uvicorn / YandexGPT).
  * Слушает порт: `8000`
  * Документация API: `http://localhost:8000/docs`
  * Эндпоинт анализа: `POST /analyze`
  * Хранилище данных: монтируемый каталог `./hr_exit_engine/data` -> `/app/data`
* **`hr_exit_web/`** — Фронтенд на JavaScript/TypeScript (React + Vite).
  * Слушает порт: `5173`
  * Пользовательский интерфейс: `http://localhost:5173`
* **`process_test_cases.py`** — Утилита пакетной обработки тестовых и реальных кейсов через REST API.

---

## 📋 Системные требования

* **Docker Desktop** (версии 20.10+ с поддержкой Compose V2).
* **PowerShell 5.1+** или **PowerShell 7+** (для Windows) / Bash (для Linux/macOS).
* **Python 3.10+** (для локального запуска утилиты пакетного тестирования).
* Убедитесь, что Docker Desktop запущен и находится в статусе **Engine running**.

## 🚀 Быстрый запуск серверов через Docker

Все команды выполняются из корневой папки проекта (`C:\hakaton`):

### 1. Первоначальная сборка и запуск
Собрать образы и запустить оба контейнера в фоновом режиме:
```powershell
docker compose up -d --build
```

### 2. Повседневный запуск и остановка
* **Запустить проект:**
  ```powershell
  docker compose up -d
  ```
* **Остановить контейнеры:**
  ```powershell
  docker compose stop
  ```
* **Остановить и удалить контейнеры:**
  ```powershell
  docker compose down
  ```

### 3. Проверка статуса сервисов
```powershell
docker compose ps
```
Оба контейнера (`hr_exit_web` и `hr_exit_engine`) должны находиться в статусе **Up**.

## 📊 Пакетная обработка данных (`process_test_cases.py`)

Для валидации моделей и анализа набора данных exit-интервью в пакетном режиме используется скрипт `process_test_cases.py`.

### Что делает скрипт:
1. Загружает набор кейсов интервью (тексты бесед, причины, маркеры).
2. Поочередно отправляет запросы на эндпоинт `POST http://localhost:8000/analyze`.
3. Анализирует ключевые сущности:
   * **Зона риска** (`risk_zone`);
   * **Основная причина ухода** (`exit_reason`);
   * **Боли и триггеры** (`pain_points`);
   * **Положительные практики** (`best_practices`);
   * **Рекомендации по улучшению** (`improvement_suggestions`).
4. Формирует и выводит сводный отчет (паспорт интервью) в консоль.

### Запуск пакетной обработки:

> **Важно:** Перед запуском убедитесь, что бэкенд запущен (`docker compose up -d`) и отвечает по адресу `http://localhost:8000`.

**Шаг 1. Активируйте виртуальное окружение и установите `requests` (если не установлены):**
```powershell
.\hr_exit_engine\.venv\Scripts\Activate.ps1
pip install requests
```

**Шаг 2. Запустите обработку:**
```powershell
python process_test_cases.py
```

## ⚠️ Устранение неполадок (FAQ)

1. **`Connection refused` при запуске `process_test_cases.py`:**
   * Убедитесь, что контейнер `hr_exit_engine` запущен и проброшен порт `8000:8000`. Проверьте статус через `docker ps`.
2. **`Container is restarting` (Бэкенд падает):**
   * Проверьте команду запуска в `docker-compose.yml`: должна быть указана `command: uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload`.
3. **Ошибки кодировки `requirements.txt` (`ï»¿fastapi`):**
   * Файл сохранен с сигнатурой UTF-8 BOM. Пересохраните его в UTF-8 без BOM.
